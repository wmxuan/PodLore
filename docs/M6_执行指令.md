## 三、M6 执行要点（Trae 注意）

### 1. embedding（bge-small-zh-v1.5，本地）
- sentence-transformers 加载，**惰性加载**（首次搜索才加载，避免启动慢）
- ⚠️ **版本兼容已知风险**（M0 时确认过）：transformers 5.x 要求 torch≥2.5，本机 torch 2.2.2 → **需降级 transformers<5 + 联动 sentence-transformers 版本**。若加载失败，报告 + 等决策，不要硬凑
- 模型缓存重定向 data/models/（沿用 config.py 机制）

### 2. 向量存储与检索（万级以内，numpy 够用）
- 数据量：几十本书 × 每本几十段 = 千级段落，numpy + 余弦相似度足够（不用向量数据库）
- `build_index()`：遍历 book_paras 向量化，存 data/vectors/（npy + 元数据 json）
- `search(query, top_k=10)`：query 向量化 → 余弦 top_k → 返回 `{book_id, book_title, chapter, para_text, score}`
- **增量更新**：新书加入后 reindex（全量重建，千级秒级）
- 段落级索引：**book_paras**（用户精编后的书），不是 transcript_paras

### 3. 检索策略：向量为主 + FTS 兜底（防漏）
- 先向量检索 top_k
- 向量结果不足或分数低时，用 SQLite FTS（M5 的 LIKE 搜索升级为 FTS5 或保留 LIKE）补关键词命中
- 合并去重，返回带来源（书/章节/段落）
- **返回带上下文**：命中的段落 + 前后段落（阅读体验）

### 4. 评测集（关键——Recall@K ≥ 0.7 怎么测）
- `eval/dataset/search_queries.jsonl`：**30-50 条**，格式：
  ```json
  {"query": "营销怎么建立护城河", "expected_book_ids": [1, 2], "expected_keywords": ["护城河", "差异化"]}
  ```
- **标注方法**（你本人标注，基于真实转写的书）：
  - 从已有书（声动早咖啡等）提取真实主题 → 写查询 → 标记「哪些书应该有这个内容」
  - 覆盖：精确词（书里有原词）/ 语义词（书里没有原词但意思相关——**这是语义搜索的价值点，要多标这类**）/ 跨书（一个 query 期望多本书）
- `backend/scripts/eval_search.py`：跑评测 → 对每条 query，取 top-K 结果，**检查是否包含 expected_book_ids** → Recall@K = 命中的 query 数 / 总数 → 输出报告
- **K 取多少**：top-10（Recall@10 是合理口径）
- 验收线：**Recall@10 ≥ 0.7**（30+ 条里 ≥ 21 条命中）

### 5. API 升级
- `GET /api/search?q=&top_k=`：从 M5 的 SQLite LIKE 升级为语义引擎（交互不变，前端不动或微调）
- 响应保持 M5 结构（book_id/para_id/chapter_title/para_text + score），前端「附加到笔记」兼容

### 6. 测试要求
- embedding mock（注入 fake embedder）：search 返回结构正确、来源字段完整
- 评测脚本可运行输出指标
- 真实验证：用已有书跑几条真实 query（如「美妆」「洗护」），人工检查召回质量
