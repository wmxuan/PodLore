## 一、成果总览

第一期用 8 个里程碑，把「贴一个小宇宙链接 → 得到一本可读可标注可检索的书」跑成了一条全本地、async、有测试兜底的链路。

| M | 里程碑 | 交付物 | 状态 |
|---|---|---|---|
| M0 | 工程骨架 | venv / FastAPI / Vite / 3 个 FunASR 模型下载验证 | ✅ |
| M1 | 数据抓取 | 小宇宙页面解析 + 音频流式下载 + 幂等入库 | ✅ |
| M2 | 本地转写 | FunASR SenseVoiceSmall + vad + punc → transcript_paras | ✅ |
| M3 | AI 加工 | DeepSeek JSON mode → 大纲 / 金句溯源 / 广告保守 / 分块摘要 | ✅ |
| M4 | 精编成书 | 冻结快照三表（books/book_chapters/book_paras）+ edits 数组 | ✅ |
| M5 | 阅读器 | 播放同步 + 划线笔记锚定 + 选中搜索 + 标注列表 | ✅ |
| M6 | 语义搜索 | bge embedding + numpy 余弦 + FTS/LIKE 兜底 + 40 条评测 | ✅ |
| M7 | 首页知识宇宙 | /api/home jieba 词云（标注加权）+ 足迹 + 书架 + 数据成就 | ✅ |

### 核心产品闭环：数据飞轮

> 用户读 → 标注（划线/笔记）→ SQLite → jieba 加权重算词云 → 首页刷新即变 → 点词云跳搜索 → 找回读过的内容 → 继续标注

词云权重设计（笔记×2 / 划线×1 / 摘要×1）让「用户行为 = 数据」落地，标注驱动的词云比纯摘要提取更能反映「我读过什么」。

## 二、工程亮点（面试可讲）

1. **全本地 + async**：ASR / embedding / 检索均本地，数据不出本机；FastAPI async 全链路，aiosqlite 异步驱动。
2. **数据诚实**：首页空态不造假（专项 pytest 守底线）；Recall 指标如实说明局限性（同话题三版本虚高，跨话题待验证）。
3. **金句溯源**：AI 加工的每条金句带 `para_id`，可定位回原文，不是凭空生成。
4. **三表冻结快照**：编辑用 edits 数组，不破坏原文，可追溯 / 可回滚，标注锚定稳定。
5. **三通道混合搜索 + 染色可溯源**：vector（绿）/ fts（黄）/ like（红）结果染色，用户知道每条结果怎么来的。
6. **100 个 pytest + 一键冒烟**：85 主链路 + 15 ASR；冒烟脚本能当场验证「真的能跑」。
7. **工程约束处理**：Intel Mac torch 上限 2.2.2 → 锁定 transformers 4.47.1 + sentence-transformers 3.3.1；numpy<2；cryptography<49 / numba<0.63 / llvmlite<0.46 全为 Intel Mac wheel 兼容。

## 四、面试要点提炼

1. **一句话定位**：把播客变成可读可标注可检索的「书」，全本地链路。
2. **数据飞轮**：标注反哺词云，用户行为 = 数据，不是静态收藏。
3. **诚实边界**：Recall@10=1.0 但如实说明是同话题三版本——验证链路可用，不夸大效果。
4. **工程深度**：async 全链路、三表冻结快照、金句溯源、三通道染色可溯源、Intel Mac 版本兼容预案。
5. **产品决策**：成书默认原稿一键可用（避免编辑过重致成书率低）、空库不造假、搜索理念文案化。
