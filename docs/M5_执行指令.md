## 三、M5 执行要点（Trae 注意）

### 1. 播放器同步（核心体验，关键实现）
- 音频源：`episodes.audio_url`（m4a 直链）——**用书关联的 episode 的 audio_url**
- HTML5 Audio + 段落时间戳匹配：`book_paras` 带 `start_ts/end_ts`（M4 已存）
- 播放时：找到 `currentTime ∈ [start_ts, end_ts]` 的段落 → 高亮 + 自动滚动到可视区（scrollIntoView，平滑）
- 点击段落 → 跳转播放（audio.currentTime = 段落 start_ts）
- **交互细节**：高亮段落要「跟随播放自动滚动」，但用户手动滚动阅读时**不要抢滚动**（打断阅读体验）——用「用户是否在滚动」判断，或点击播放器播放后才自动跟随

### 2. 划线 + 笔记（对标微信读书）
- 选中文本 → 浮动操作条（划线 / 笔记 / 搜索）
- 划线：高亮该段选中文本（灰蓝背景），存 annotations（color='blue'）
- 笔记：弹出输入框，保存 `note_text`
- **标注锚定**：`{book_id, book_para_id, offset_start, offset_end}`——书冻结，永不错位
- 标注在段落内的定位：用 `offset_start/offset_end`（相对段落文本的字符偏移）——段落文本不变（冻结），偏移稳定

### 3. 选中搜索（对标微信读书）
- 操作条「搜索」→ 调 `GET /api/search?q=选中文本`（M6 实现，**M5 先占位**：返回「语义搜索 M6 建设中」提示，或先做简单关键词搜索兜底）
- M5 的验收重点是**交互链路**（选中→搜索→结果→附加到笔记），搜索结果本身 M6 完善
- 建议 M5 先用 SQLite LIKE 简单搜索占位，把交互跑通

### 4. 标注列表页
- 按书聚合展示全部标注（划线内容 + 笔记）
- 点击标注 → 回跳阅读器对应段落（book_id + para_id → 滚动定位 + 高亮）
- 删除标注（标注列表可删）

### 5. 数据模型（M5 新增）
```sql
CREATE TABLE IF NOT EXISTS annotations (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  book_id INTEGER, book_para_id INTEGER,
  offset_start INTEGER, offset_end INTEGER,
  color TEXT DEFAULT 'blue', note_text TEXT,
  created_at TEXT DEFAULT (datetime('now'))
);
```

### 6. 阅读器视觉（ins 规范，延续 M4）
- 正文：细无衬线、行距 1.7、奶油白底
- 章节导航：细线侧栏或顶部（可折叠）
- 播放器：底部毛玻璃条（收起态），播放时展开
- 划线高亮：灰蓝；笔记标记：段落右侧细线标记
- 标注列表：ins 卡片列表

### 7. 测试要求
- 后端：标注 CRUD 全通（pytest）；标注锚定（offset 正确）
- 前端：手工验证三大交互（播放高亮 / 划线笔记 / 选中搜索）在真实书上可用
- 路由：/books/:id（阅读器）/annotations（标注列表）
