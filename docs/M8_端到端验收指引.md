## 一、导入 5 本真实播客（建议跨话题）

建议话题组合（保证跨话题评测有区分度）：

| 话题 | 推荐播客 | 用途 |
|---|---|---|
| 商护发 / 美妆 | 半拿铁（护发 / 美妆相关单集） | 已有评测集基线 |
| 商业 / 创业 | 纵横四海（雷军 / 创业类单集） | 跨话题对照 |
| 营销 / 品牌 | 任意营销类单集 | 跨话题对照 |
| AI / 科技 | 任意 AI 类单集 | 跨话题对照 |
| 管理 / 组织 | 任意管理类单集 | 跨话题对照 |

**操作**：

1. 前端首页 / 书架页点「导入」→ 粘贴小宇宙链接
2. 等待 抓取 → 转写（1 小时音频约 10-20 分钟 CPU）→ 成书
3. 5 本都成书后，记录每本的 `book_id`（编辑器 URL `/books/:id` 里的 id）

> 如果时间紧，至少导入 2 本不同话题的（如 1 本护发 + 1 本商业），足以验证跨话题区分度。

## 二、阅读器：边听边读边标注（验证标注链路）

挑 1 本听过的书，进阅读器 `/books/:id`：

- [ ] **播放同步**：点播放，逐字稿随时间码自动滚动
- [ ] **划线**：选中一段文字 → 划线（选个颜色）
- [ ] **笔记**：在划线上加一条文字笔记（如『欧莱雅护发战略』）
- [ ] **选中搜索**：选中一段话 → 点搜索 → 跳搜索页有结果
- [ ] **标注列表**：书内标注列表能看到刚划的线 + 笔记
- [ ] **刷新不丢**：刷新阅读器，划线 / 笔记还在（锚定 book_para_id + offset）

> 关键：记下你划线 / 记笔记时用的**关键词**（如『欧莱雅』『护发战略』），下一步验证词云会用到。

---

## 三、语义搜索：搜你听过的内容（验证召回）

进搜索页 `/search`：

- [ ] 搜一个你听过的**观点**（不是字面关键词，如『国货在洗护市场的机会』）→ 能召回相关段落
- [ ] 结果按来源（书 / 章 / 段）展示，有上下文
- [ ] 结果染色可溯源（vector 绿 / fts 黄 / like 红）
- [ ] 从首页词云点 chip 跳转 → `/search?q=词` 自动搜索

---

## 四、首页数据飞轮：先划线再回首页看词云变化（核心验证）

这一步验证「用户行为 = 数据」的闭环：

1. **先看首页词云现状**（截图 1 · 首页）——此时若没划过线，词云主要来自摘要提取
2. 回阅读器，**真实划几条线 + 记几条笔记**（用你想让它出现在词云里的词，如反复划『护城河』『差异化』相关段落）
3. **回到首页刷新** → 词云应该出现 / 权重上升你刚标注的词
4. [ ] **词云从「摘要提取」变成「标注驱动」**（笔记×2 / 划线×1 加权，标注词权重更高）

> 这就是数据飞轮：你读了什么 → 标注了什么 → 词云反映什么 → 点词云又能搜回去。

## 五、跨话题评测（M6 遗留项，补齐区分度验证）

导入不同话题书后，补跨话题评测验证「语义搜索真的能区分不同话题」：

1. 查到各话题书的真实 `book_id`（编辑器 URL 里取）
2. 编辑 `eval/dataset/search_queries_cross_topic.jsonl`，把 `<商业类 book_id>` 等占位符替换成真实 id
3. 重跑评测：

```bash
backend/.venv/bin/python backend/scripts/eval_search.py \
  --dataset eval/dataset/search_queries_cross_topic.jsonl \
  --report-json eval/reports/cross_topic_eval_report.json
```

4. [ ] **区分度验证**：跨话题 query 应只命中对应话题书
   - 如「雷军 小米 创业 经历」→ 只命中商业书，不命中护发书
   - 如「护肤 成分 烟酰胺 视黄醇」→ 只命中美妆书，不命中商业书
5. 记录 Recall@10（跨话题口径），填进 M8 验收报告

> 诚实预期：若某些 query 跨话题区分度不够（比如两个话题共用『品牌』『增长』等词），如实记录——这正是第二期要优化的方向。
