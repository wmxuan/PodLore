## 三、M4 执行要点（Trae 注意）

### 1. 核心设计：书 = 冻结快照（不可违背）
- 书的三表（books/book_chapters/book_paras）与转写稿（transcript_paras）**完全分离**
- create_book 时从 transcript_paras 生成 book_paras（应用编辑），**之后不再随转写变化**
- 同一集重复建书 → 新 book_id（version+1），**不覆盖旧书**
- 这是「标注永不错位」的根基，M5 阅读器依赖它

### 2. 编辑模型（API 设计）
```
GET /api/episodes/{eid}/transcript   → 转写稿 + 广告标记 + 金句（编辑页数据）
POST /api/episodes/{eid}/book        → 创建书
  body: { edits: [{para_id, action: 'keep'|'replace'|'delete', new_text?}] }
  → 生成 book_paras（keep 原样 / replace 换文本 / delete 跳过）
  → 返回 book_id
```
- 前端把「段落列表 + 用户操作」组装成 edits 提交
- 广告段落：前端一键「删除/保留」→ 对应 delete/keep action

### 3. 章节结构（book_chapters）
- 用 M3 的 episode_outline 生成章节（大纲的 start_ts 切分）
- 无大纲兜底：单章「全文」
- 每段归属章节：按时间戳匹配（start_ts 落在哪个章节区间）

### 4. 前端编辑页（交互设计，M4 主体工作量）
- **段落列表**：转写稿逐段展示（已按 50-200 字段落化），广告段高亮标记（陶土橘）
- **AI 建议区**：广告段「删除/保留」一键按钮（ins 风格，细线按钮）
- **段落编辑**：点击段落可编辑文本（textarea 或 contenteditable）——纠错/改写
- **段落删除**：每段「删除」按钮
- **「加入书架」**：固定底部按钮，点击生成书 → 跳书架页
- **设计规范**：奶油白底、灰蓝强调、大圆角、细线（PRD §4.4 CSS 变量）
- **编辑状态**：已编辑段落显示标记（如段落边框变色），用户知道改了什么

### 5. 书架页（前端）
- 书卡片：封面（复用播客封面✅）/ 标题 / 章节数 / 创建时间
- 点击进书 → 占位（M5 阅读器，先跳空白页或提示「M5 开发中」）
- ins 网格布局（3 列）

### 6. 测试要求
- 后端：创建书（无编辑/删除 2 段+改写 1 段）断言 book_paras 正确；幂等（重复建书新 id）；章节归属正确
- 前端：手工验证编辑→成书全流程
