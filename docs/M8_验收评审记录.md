## 三、🔧 测试隔离修复（本期重要质量改进）

### 问题

M7 代码（770348c）全量 `pytest backend/tests` 实际是 **10 failed / 92 passed**（非评审记录所述 100 passed——此前 100 是按 "85 主链路 + 15 ASR 单独" 拆分跑得来）。已用 `git stash` 在干净树复现确认，与 M8 改动无关，是 M7 遗留。

**根因**：
1. `app/main.py` lifespan shutdown 调 `transcribe_service._executor.shutdown()` / `process_service._executor.shutdown()`，关闭模块级单例线程池。任何用真实 app 的 API 测试（TestClient）触发 lifespan 后，后续 worker 服务测试 `start_transcribe()` submit 即抛 `RuntimeError: cannot schedule new futures after shutdown`（9 个 worker 测试挂）。
2. `test_api_search_m6` 的 `from backend.scripts import eval_search` 依赖 `backend` 作为命名空间包（无 `__init__.py`），repo root 不在 sys.path 时 `ModuleNotFoundError: No module named 'backend'`（1 个测试挂）。

### 修复（最小、干净、保留生产行为）

| 文件 | 改动 |
|---|---|
| `app/services/transcribe_service.py` | `_executor` 改惰性创建 + `_get_executor()` 检测 `_shutdown` 后自愈重建；`start_transcribe` 走 `_get_executor()` |
| `app/services/process_service.py` | 同款惰性 `_get_executor()` |
| `app/main.py` | lifespan shutdown 加 None + `_shutdown` 守卫，非阻塞关闭语义不变 |
| `backend/tests/conftest.py` | 补 repo root 进 sys.path，让 `backend.scripts.*` 命名空间包可导入 |

### 结果

```
backend/.venv/bin/pytest backend/tests -q  →  102 passed in 49.35s ✅
```

**一次性全绿，不再需要 "85+15 单独" 拆分**。生产非阻塞 shutdown 行为保留，测试隔离自愈。
